# prep: 지하철 데이터 정리

국가철도공단 파일 두 개를 경로 엔진이 쓸 표로 바꾼다.

## 입력 (상위 폴더 또는 `데이터/` 폴더에 둔다)

- `전체_도시철도운행정보_*.xlsx`: 열차번호, 정거장별 도착·출발 시각
- `전체_도시철도역사정보_*.xlsx`: 역 좌표, 환승, 운영기관

## 실행

```
pip install pandas openpyxl
python prep/parse_rail.py
```

1~2분 걸린다. 결과는 `prep/out/`에 생긴다.

## 출력

| 파일 | 내용 |
|---|---|
| `stop_times.csv` | 열차(trip_id)·정거장(seq)별 `arr_sec`, `dep_sec`. 운행일 기준 초라서 자정 이후는 86400(24:00)을 넘는다. `service_days`는 WD/SAT/HOL. `place_id`로 역을 찾는다 |
| `stations.csv` | 역사정보 + `place_id`(같은 이름, 700m 안 = 한 장소 = 환승역) + `coord_suspect`(주소와 좌표가 안 맞음) |
| `name_aliases.csv` | 운행정보의 역 이름 → 장소 대응. `needs_review=True`는 사람이 확인 |
| `report.txt` | 노선별 열차 수, 기준일, 평일 마지막 출발, 품질 문제 목록 |

`manual_aliases.csv`에 코레일 줄임말(예: `디엠시` → 디지털미디어시티)을 직접 적는다. 전부 '추정'이니 확인 후 status를 바꾼다.

## 처리 규칙

- 형식 세 가지를 읽는다: 정거장마다 한 줄(코레일), 열차 한 줄에 `001-성수+002-뚝섬`(서울교통공사 등), 쉼표 구분(7호선 연장 구간)
- `00:00`은 빈 값 표시로 본다. 03시 이전 시각은 전날 운행일의 연장(24시 이후)으로 바꾼다 (신분당선·9호선은 자정 이후를 `00:10`으로 적는다)
- 같은 열차가 서울교통공사 형식과 코레일 형식에 모두 있으면 서울교통공사 형식을 남긴다. 단, 그쪽이 suspect면 코레일 형식을 남긴다
- 정차역 절반 이상이 천안 이남인 열차(대구권 광역철도 등)는 뺀다

## quality 값

| 값 | 뜻 | 엔진에서 |
|---|---|---|
| `ok` | 문제 없음 | 사용 |
| `suspect_geo` | 좌표로 본 이동 속도가 130km/h를 넘음. 역 이름과 시각이 어긋난 열차 | 쓰지 않거나 검증 후 사용 |
| `suspect_arr`, `suspect_order` | 도착/출발 시각 순서가 맞지 않음 | 위와 같음 |
| `dep_from_arr` | 출발 시각이 거꾸로 적혀 도착 시각으로 대신함 (신림선 일부) | 사용 (정차 시간 오차 1분 이내) |

## 알려진 문제 (2026-06-30 파일 기준)

- **1호선 경인 구간(구로~인천)**: 서울교통공사 형식 일부 열차의 역 이름이 시각과 어긋나 있다. suspect_geo 295개가 남아 있다 (코레일 형식으로 대신할 수 있는 161개는 바꿨음). 서울 안의 구일·개봉·오류동·온수가 영향을 받는다
- **양원역(경의중앙선)**: 역사정보 좌표가 경북으로 잘못 들어 있다. 직접 고쳐야 한다
- **데이터 기준일**: 우이신설선 2022-05, 신림선 2025-09, 서울 1~8호선 2025-12. 막차 몇 개를 운영사 안내와 대조해야 한다
- **GTX-A**: 파일에 없다

# 버스 데이터 정리 (`parse_bus.py`)

## 입력 (`데이터/` 폴더)

- `seoul_route_master.csv`, `seoul_station_master.csv`, `seoul_route_node.csv`: `python prep/fetch_seoul_master.py`로 받는다
- `tpss_route_section_speedh_*.zip`: 서울 열린데이터광장 OA-21217. 최신 `N_WEEKS`(기본 2)주만 쓴다
- `서울시버스노선기본정보(YYYYMMDD).xlsx`: 가장 최신 파일만 쓴다

## 실행

```
python prep/parse_bus.py
```

40초쯤 걸린다.

## 출력 (`prep/out/`)

| 파일 | 내용 |
|---|---|
| `bus_routes.csv` | 서울 노선 717개. `WD/SAT/HOL_first_sec`, `_last_sec`(기점 출발, 운행일 기준 초), `_headway_min`(평균 배차), `_headway_lo/hi`(최소·최대 배차) |
| `bus_stops.csv` | 정류장. `has_coord=0`은 좌표 없음 (대부분 서울 버스가 지나는 경기도 정류장) |
| `bus_route_stops.csv` | 노선별 `seq`, `stop_id`, `dist_from_prev_m`, `cum_dist_m` |
| `bus_segments.csv` | 구간(seq-1 → seq) 운행시간(초). `wd_med_h23` = 평일 23시 중앙값, `we_p90_h00` = 주말·공휴일 00시 90% 값. `no_section_data=1`은 실측이 없어 추정한 구간 |
| `bus_report.txt` | 요약, 막차 시뮬레이션 예시, 확인 필요 항목 |

## 처리 규칙

- 막차가 첫차보다 이르면 자정을 넘긴 것으로 보고 86400을 더한다. 첫차가 03시 이전이면(N26 `00:00`) 첫차·막차 모두 24시 이후로 본다
- 공동배차 노선은 회사별로 행이 나뉘어 있지만 값이 같아서 하나만 남긴다
- 노선 번호가 같은 RTE_ID가 여럿이면 정류장 순서가 있고 거리가 기본정보와 가까운 쪽을 고른다
- 구간 운행시간은 순서 번호가 아니라 (앞 정류장, 다음 정류장) ID 쌍으로 잇는다. 정류장 순서가 바뀐 노선은 번호가 밀리기 때문이다
- 빈 시간대는 가까운 시간대 값 → 다른 요일 유형 값 → 구간 평균 → 거리/20km/h 순서로 채운다. 같은 거리면 앞 시간대(더 막히는 쪽)를 쓴다
- 엔진에서는 기점 막차 시각부터 시간대별 구간 시간을 더해서 정류장별 도착 시각을 구한다 (`simulate()` 참고)

## 알려진 문제

- 평일 00시에 실측이 있는 구간은 49%, 01시는 16%뿐이다. 나머지는 23시 값으로 채워서 심야에는 실제보다 조금 느리게 잡힌다(안전한 쪽)
- 노선 `2312`는 route_master에 없다. route_master를 다시 받아 봐야 한다
- 기본정보의 `541` 운행시간이 1190분으로 잘못 적혀 있다 (구간 합계는 187분)
- 한강버스(선박) 노선이 섞여 있다. 엔진에서 뺄지 정해야 한다
- 공휴일은 `HOLIDAYS`에 직접 적는다. 나중에 특일 정보 API로 바꾼다

# 환승 도보 연결 (`build_transfers.py`)

`parse_rail.py`, `parse_bus.py` 다음에 실행한다. 10초쯤 걸린다.

```
python prep/build_transfers.py
```

## 출력 (`prep/out/`)

| 파일 | 내용 |
|---|---|
| `transfers.csv` | `from_kind,from_id → to_kind,to_id`, `dist_m`(직선), `walk_sec`. kind는 `rail`(place_id) 또는 `bus`(stop_id). 양방향 모두 적는다 |
| `transfers_report.txt` | 종류별 개수, 정류장이 없는 역, 역 근처 정류장 예시 |

같은 `place_id` 안의 환승(예: 2호선 ↔ 신분당선 강남)은 여기 없다. 엔진의 역 내 환승 기본값으로 처리한다.

## 규칙

- 직선거리 한도: 역↔정류장 400m, 정류장↔정류장 250m, 이름이 다른 역끼리 400m
- 걷는 시간 = 직선거리 × 1.3(우회) ÷ 1.1m/s + 역 쪽 끝마다 120초(승강장 ↔ 지상)
- 역 좌표는 노선마다 따로 있어서, 정류장까지 거리는 그중 가장 가까운 것으로 잡는다
- `manual_coords.csv`: 역사정보 좌표가 틀린 역을 직접 고친다 (이촌 4호선, 마곡 5호선, 양원). 지금은 `build_transfers.py`에서만 쓴다

## 결과 (2026-11-08)

- 역 555곳, 정류장 11,177개. 역↔정류장 4,616쌍, 정류장↔정류장 74,098쌍(한 방향 기준), 역↔역 5쌍
- 400m 안에 정류장이 없는 역 244곳은 모두 경기·인천 (서울 버스 데이터만 있어서)
- 총신대입구(이수) 4호선과 이수 7호선은 place_id가 달라서 역↔역 0m 연결로 이어진다

# 정류장별 공식 첫차·막차 (`fetch_bus_times.py`)

공공데이터포털 **서울특별시_버스도착정보조회** `getArrInfoByRouteAll`로 노선마다 정류장별 첫차·막차 예정 시각을 받는다. 노선 717개를 한 번씩 조회한다 (약 3분).

```
python prep/fetch_bus_times.py
```

- 인증키: `데이터/seoul_key2.txt` 첫 줄
- **API는 조회한 날의 운행 기준 값을 준다.** 평일(월~금), 토요일, 일요일·공휴일에 각각 한 번씩 돌려야 세 가지가 모두 모인다. 운행일은 03시에 바뀐다
- 출력: `데이터/bus_stop_times_YYYYMMDD_<WD|SAT|HOL>.csv`. 중간에 끊기면 다시 실행할 때 받은 노선은 건너뛴다
- 엔진은 요일 유형마다 가장 최신 파일을 쓴다. 파일이 없는 유형은 예전처럼 기본정보 막차 + 구간 시간으로 추정한다

## 받은 데이터의 특징 (2026-11-08 HOL)

- 정류장 41,635행 중 약 10%는 값이 비어 있다 (`2026110800`). 주로 기점
- 첫 정류장 막차가 25:00으로 적히는 등 튀는 값이 섞여 있다 → 엔진에서 거른다
- 늦은 버스가 노선 끝까지 가지 않는 **단축 운행** 노선이 있다 (뒤쪽 정류장의 막차가 더 이르다). 104개 노선
